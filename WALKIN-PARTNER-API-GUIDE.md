# Walk-in Competition — Partner REST API Guide

**Malaysia Techlympics (MT) platform · for partner applications**

This guide describes the REST API a partner application must expose so that
Malaysia Techlympics can run one of the partner's challenges as a **walk-in
competition**: participants register at an on-site counter (or in the MT
participant portal), receive an entry token, play on the partner's
kiosk/app, and their results flow back to MT for judging, ranking and
announcement.

It is the recommended contract for **new** walk-in partners. It follows the
model of MT's current walk-in integrations; partners integrated earlier under
the older "partner issues the token" pattern (`THIRD_PARTY_INTEGRATION_GUIDELINE.md`,
§5) remain supported.

## 1. How a walk-in competition works

| Step | Who | What happens |
|---|---|---|
| 1 | MT organizer | Picks one of your **challenges** for a walk-in competition of an MT event. |
| 2 | MT → you | MT creates an **event** on your platform for that competition (name, round, schedule, run duration). |
| 3 | Participant | Registers for the walk-in competition — at the MT counter or in the MT portal — and is confirmed. |
| 4 | MT → you | MT generates an **entry token** and registers an **entry** with you, carrying the token and MT's own reference. |
| 5 | Participant | Is handed the token (printed / on screen) and enters it on your kiosk or app to start their run. |
| 6 | Counter staff | If a token is lost or mistyped, asks MT to **replace** it; the old token stops working immediately. |
| 7 | MT → you | MT **queries results** for its entries (status, stages completed, official time, rank) to show progress, judge and rank. |
| 8 | MT organizer | Closes the event on your platform when the competition ends. |

**Every call is made by MT's server to yours.** Your API is never called from a
browser, and you never need to call MT.

---

## 2. Core concepts

| Concept | Meaning | Identifier |
|---|---|---|
| **Challenge** | A playable game/mode on your platform (e.g. "City Builder"). Created and maintained by you. | `challenge_id` — yours |
| **Event** | One run of a challenge for one MT walk-in competition (e.g. "Zon Selatan · Qualifier"). Created by MT through your API. | `event_id` — **chosen by MT**, unique, URL-safe |
| **Entry** | One participant's place in an event. Registered by MT, one per confirmed walk-in registration. | `entry_id` — yours, returned on registration |
| **Entry token** | The short code the participant types on your kiosk to start. **Generated by MT**, stored by you. | `entry_token` — 8 chars `A-Z0-9` |
| **Partner reference** | MT's opaque reference for the registration, echoed back in results so both sides can reconcile. | `partner_reference` — MT's, ≤ 64 chars |

Rules of thumb:

- One **event** per MT walk-in competition (or per session, if a competition runs in several).
- One **entry** per participant per event. Registering the same `partner_reference` again must not create a second entry.
- One **active token** per entry at a time.

## 3. Authentication & transport

- **HTTPS only**, TLS 1.2+.
- Every request carries a secret key:

  ```http
  X-API-Key: <key issued by you to MT>
  Content-Type: application/json
  Accept: application/json
  ```

- Issue MT a **separate key per environment** (staging, production). A key should
  only see the events created with it.
- Reject a missing or wrong key with `401`; a valid key without access to a
  resource with `403` (or `404`, to avoid revealing it exists).
- Keys must be revocable and rotatable without downtime (allow two active keys
  during a rotation).
- MT calls from fixed server IPs — ask the MT team if you want an allow-list.

**Base path:** all endpoints below are relative to your base URL, e.g.
`https://api.partner.example/v1/partner`.

---

## 4. Conventions

- **JSON** request and response bodies, UTF-8.
- **Timestamps:** ISO 8601 in UTC, e.g. `2026-11-15T01:30:00.000Z`.
- **Durations:** integers — seconds for configuration (`run_duration_sec`),
  milliseconds for results (`official_elapsed_ms`).
- **Field names:** `snake_case`.
- **Null vs. absent:** send `null` for "known to be empty"; do not omit documented fields.
- **Idempotency:** every write MT makes is safe to retry. Creating something that
  already exists returns the existing object with an `already_*: true` flag and
  `200`, never a duplicate and never an error.
- **Timeouts:** MT waits **10 seconds** per call. Aim for < 1 s at the 95th
  percentile; the counter queue is waiting.
- **Pagination:** none of these endpoints need it — batch sizes are capped instead.

## 5. Endpoint reference

| # | Method & path | Purpose |
|---|---|---|
| 5.1 | `GET /health` | Configuration check |
| 5.2 | `GET /challenges` | Challenges an organizer can pick |
| 5.3 | `POST /events` | Create the event for a walk-in competition |
| 5.4 | `PATCH /events/{event_id}` | Update schedule, open / close |
| 5.5 | `GET /events` | Events visible to the key |
| 5.6 | `POST /events/{event_id}/entries` | Register a participant's entry with its token |
| 5.7 | `PUT /events/{event_id}/entries/{entry_id}/token` | Replace an entry's token |
| 5.8 | `POST /events/{event_id}/results:query` | Results for a batch of entries |

### 5.1 `GET /health`

Used when an organizer enables the integration, to confirm URL and key.

```json
{ "status": "ok", "service": "partner-arena", "version": "1.4.0" }
```

`200` when healthy and the key is valid; `401` for a bad key.

### 5.2 `GET /challenges`

Optional query: `status` (`active` | `draft` | `archived`).

```json
{
  "challenges": [
    {
      "id": "ch_city_builder",
      "name": "City Builder",
      "description": "Build the tallest stable structure.",
      "challenge_mode": "timed",
      "status": "active",
      "order_index": 1,
      "created_at": "2026-09-01T00:00:00.000Z"
    }
  ]
}
```

| Field | Notes |
|---|---|
| `id` | Stable; MT stores it with the walk-in competition. |
| `challenge_mode` | Free text describing how a run is scored, e.g. `timed`, `score`, `stages`. |
| `order_index` | Display order in MT's picker. |

### 5.3 `POST /events`

Creates the event MT will register entries into. **MT chooses `event_id`**, so a
retry after a timeout cannot create a second event.

Request:

```json
{
  "event_id": "mt-zon-selatan-3-2r-q1",
  "challenge_id": "ch_city_builder",
  "name": "Zon Selatan · 3.2R Robotik · Qualifier",
  "competition_round": "qualifier",
  "starts_at": "2026-11-15T01:00:00.000Z",
  "ends_at":   "2026-11-15T09:00:00.000Z",
  "run_duration_sec": 600
}
```

| Field | Required | Notes |
|---|---|---|
| `event_id` | yes | `[a-z0-9-]`, ≤ 64 chars, unique on your platform |
| `challenge_id` | yes | From 5.2; `422` if unknown or not `active` |
| `name` | yes | Shown on your kiosk / leaderboard |
| `competition_round` | yes | `qualifier` \| `final` |
| `starts_at`, `ends_at` | yes | Tokens are only accepted inside this window; `ends_at` > `starts_at` |
| `run_duration_sec` | yes | Maximum length of one run; a run that exceeds it ends as `timed_out` |

Response `201 Created` (or `200` with `already_exists: true` if `event_id` exists
with the same challenge):

```json
{
  "event_id": "mt-zon-selatan-3-2r-q1",
  "challenge_id": "ch_city_builder",
  "name": "Zon Selatan · 3.2R Robotik · Qualifier",
  "status": "open",
  "starts_at": "2026-11-15T01:00:00.000Z",
  "ends_at": "2026-11-15T09:00:00.000Z",
  "run_duration_sec": 600,
  "already_exists": false
}
```

`409` if `event_id` exists with a **different** `challenge_id`.

Event `status`: `draft` (not yet playable) | `open` | `closed` (no new runs; results stay queryable).

### 5.4 `PATCH /events/{event_id}`

Partial update; any subset of `name`, `competition_round`, `starts_at`,
`ends_at`, `run_duration_sec`, `status` (`open` | `closed`).

```json
{ "ends_at": "2026-11-15T10:00:00.000Z", "status": "open" }
```

```json
{ "event_id": "mt-zon-selatan-3-2r-q1", "updated": true }
```

Closing an event must not delete entries or results. Changing `run_duration_sec`
applies to runs started afterwards only.

### 5.5 `GET /events`

Events visible to the key, newest first — used for diagnosis and to re-link a
competition.

```json
{
  "events": [
    {
      "event_id": "mt-zon-selatan-3-2r-q1",
      "challenge_id": "ch_city_builder",
      "name": "Zon Selatan · 3.2R Robotik · Qualifier",
      "competition_round": "qualifier",
      "status": "open",
      "starts_at": "2026-11-15T01:00:00.000Z",
      "ends_at": "2026-11-15T09:00:00.000Z",
      "run_duration_sec": 600
    }
  ]
}
```

### 5.6 `POST /events/{event_id}/entries`

Registers one participant's entry with the token MT generated. Called when a
walk-in registration is confirmed at the counter.

Request:

```json
{ "entry_token": "K7Q2M9XA", "partner_reference": "cmw8r1x0a000301l4f9b2c7de" }
```

| Field | Required | Notes |
|---|---|---|
| `entry_token` | yes | 8 chars `A-Z0-9`, see §6 |
| `partner_reference` | yes | MT's registration reference; **idempotency key** for the entry |

Response `201 Created`:

```json
{
  "entry_id": "ent_9f3b2c1d",
  "event_id": "mt-zon-selatan-3-2r-q1",
  "status": "ready",
  "expires_at": "2026-11-15T09:00:00.000Z",
  "partner_reference": "cmw8r1x0a000301l4f9b2c7de",
  "already_registered": false
}
```

If an entry with the same `partner_reference` already exists in the event,
return it with `200` and `already_registered: true` — **keeping its current
token** (MT will call 5.7 if it needs a new one).

| Status | When |
|---|---|
| `404` | Unknown `event_id` |
| `409` | `entry_token` already in use by another entry of the event (MT generates a new token and retries) |
| `410` | Event is `closed` |
| `422` | Malformed token or reference |

### 5.7 `PUT /events/{event_id}/entries/{entry_id}/token`

Replaces an entry's token — a lost slip, a mistyped code, or a token seen by
someone else.

```json
{ "entry_token": "P4T8W2NC" }
```

```json
{
  "entry_id": "ent_9f3b2c1d",
  "event_id": "mt-zon-selatan-3-2r-q1",
  "status": "ready",
  "expires_at": "2026-11-15T09:00:00.000Z",
  "partner_reference": "cmw8r1x0a000301l4f9b2c7de",
  "already_replaced": false
}
```

- The **old token stops working immediately**, including on a kiosk where it was
  typed but not yet submitted.
- Replacing with the token the entry already has returns `200` with
  `already_replaced: true`.
- Replacing a token does **not** reset a run already completed — that is a
  separate, deliberate organizer action (contact the MT team if you support resets).
- `404` if the entry is not in this event: MT then registers a fresh entry (5.6).
- `409` if the new token is used by another entry.

### 5.8 `POST /events/{event_id}/results:query`

Results for a batch of MT's entries — MT's progress board, judging and ranking
read from this.

```json
{ "entry_ids": ["ent_9f3b2c1d", "ent_1a2b3c4d"] }
```

Up to **500** ids per call; MT batches larger sets. Duplicates and unknown ids are
reported, not rejected.

```json
{
  "event_id": "mt-zon-selatan-3-2r-q1",
  "rank_scope": "requested_entry_ids",
  "requested_count": 2,
  "ranked_count": 1,
  "results": [
    {
      "rank": 1,
      "entry_id": "ent_9f3b2c1d",
      "status": "completed",
      "completed_stage_count": 5,
      "official_elapsed_ms": 412530,
      "score": 870,
      "max_score": 1000,
      "partner_reference": "cmw8r1x0a000301l4f9b2c7de",
      "token_expires_at": "2026-11-15T09:00:00.000Z",
      "consumed_at": "2026-11-15T02:14:03.120Z",
      "is_used": true
    },
    {
      "rank": null,
      "entry_id": "ent_1a2b3c4d",
      "status": "ready",
      "completed_stage_count": 0,
      "official_elapsed_ms": null,
      "score": null,
      "max_score": 1000,
      "partner_reference": "cmw8r1x0a000301l4f9b2c7df",
      "token_expires_at": "2026-11-15T09:00:00.000Z",
      "consumed_at": null,
      "is_used": false
    }
  ],
  "missing_entry_ids": [],
  "invalid_entry_ids": [],
  "duplicate_entry_ids": []
}
```

| Field | Notes |
|---|---|
| `status` | `ready` (not started) · `in_progress` · `completed` · `timed_out` |
| `rank` | Rank **among the requested entries only** (`rank_scope`), so MT can rank per state or per session by choosing which ids to send. `null` until the entry has an official result. |
| `completed_stage_count` | For stage-based challenges; `0` otherwise. |
| `official_elapsed_ms` | The time used for ranking; `null` until official. |
| `score`, `max_score` | For score-based challenges; `null` when not applicable. |
| `consumed_at`, `is_used` | When / whether the token was used to start a run. |
| `missing_entry_ids` | Ids not found in this event. |
| `invalid_entry_ids` | `[{ "index": 3, "value": "x" }]` — malformed ids. |

**Ranking rule:** document yours (for example: most stages, then shortest
`official_elapsed_ms`; or highest `score`, then shortest time), and apply it
identically in `rank` and on your own leaderboard. Ties share a rank.

The response must reflect a finished run within **5 seconds** — MT's boards poll
while the competition is live.

## 6. Entry tokens

- **Generated by MT**: 8 characters, uppercase `A-Z` and digits `0-9`.
- **Unique per event** among active tokens; reject a clash with `409`.
- **Case-insensitive on your kiosk**: accept `k7q2m9xa` as `K7Q2M9XA`; trim spaces.
- **Valid** from the event's `starts_at` to `ends_at` while the event is `open`.
- **One run per entry**: once a run starts, the token is consumed (`is_used: true`).
  Re-entering it may resume an `in_progress` run on the same device, but must not
  start a second ranked run.
- **Rate-limit guessing** on the kiosk (e.g. 5 wrong codes per device per minute).
- The token is the only credential the participant holds — never display another
  participant's token, and never return tokens from 5.8.

---

## 7. What the participant experiences

1. At the MT counter (or portal) their walk-in registration is confirmed and they
   receive an 8-character code.
2. On your kiosk/app they type the code; you show the event name and start the run.
3. They play until they finish or `run_duration_sec` elapses.
4. Your screen confirms completion; their result appears on MT's boards shortly
   after.

Your kiosk should show clear messages for: unknown code, code already used,
event not yet open / closed, and code replaced ("ask the counter for your new code").

## 8. Errors

Error body, for every non-2xx response:

```json
{ "error": { "code": "TOKEN_IN_USE", "message": "This entry token is already assigned in this event." } }
```

`code` is a stable machine-readable string; `message` is for logs.

| Status | Meaning | MT's reaction |
|---|---|---|
| `400` | Malformed JSON / missing field | Bug — logged, not retried |
| `401` | Missing or wrong key | Integration marked misconfigured |
| `403` | Key may not access this resource | Integration marked misconfigured |
| `404` | Event / entry not found | Re-register or ask organizer to re-link |
| `409` | Conflict (token in use, event id with another challenge) | New token and retry; or organizer action |
| `410` | Event closed | Shown to counter staff |
| `422` | Semantically invalid (unknown challenge, bad window) | Shown to organizer |
| `429` | Rate limited — include `Retry-After` | Retried after the delay |
| `5xx` | Server error | Retried with back-off; idempotency makes this safe |

## 9. Privacy & security

- **No personal data is sent.** MT shares only the entry token and an opaque
  `partner_reference`. Names, IC numbers, schools and contingents stay in MT, which
  joins your results back to participants itself. Please do not ask for more.
- Do not log full entry tokens or API keys; mask them (`K7Q2****`).
- Keep results for at least **90 days** after an event closes, for appeals and
  certificates; deleting an event must be an explicit admin action on your side.
- Report security incidents affecting MT data to the MT team within 24 hours.

## 10. Onboarding & go-live checklist

**You provide to MT**

- [ ] Staging and production base URLs
- [ ] One API key per environment (sent through a secure channel, never by email in clear text)
- [ ] At least one `active` challenge in each environment
- [ ] Your ranking rule (§5.8) and the meaning of `score` / stages for each challenge
- [ ] Rate limits and a technical contact for event days

**Before go-live, verify on staging**

- [ ] 5.1 returns `200`; a wrong key returns `401`
- [ ] 5.3 twice with the same `event_id` → one event, second call `already_exists: true`
- [ ] 5.6 twice with the same `partner_reference` → one entry, second call `already_registered: true`
- [ ] 5.6 with a token already in use → `409`
- [ ] Token typed in lower case on the kiosk works; a replaced (5.7) token is rejected at once
- [ ] A finished run appears in 5.8 within 5 seconds, with `rank` among the requested ids
- [ ] 5.8 with 500 ids answers in < 2 s
- [ ] Closing the event (5.4) blocks new runs but keeps results queryable
- [ ] Load test: 30 registrations per minute sustained, as at a busy counter

## 11. End-to-end example

```bash
BASE=https://api.partner.example/v1/partner
KEY=$PARTNER_API_KEY

# 1 — pick a challenge
curl -s "$BASE/challenges?status=active" -H "X-API-Key: $KEY"

# 2 — create the event for the walk-in competition (MT chooses the id)
curl -s -X POST "$BASE/events" -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"event_id":"mt-zon-selatan-3-2r-q1","challenge_id":"ch_city_builder","name":"Zon Selatan · 3.2R · Qualifier","competition_round":"qualifier","starts_at":"2026-11-15T01:00:00Z","ends_at":"2026-11-15T09:00:00Z","run_duration_sec":600}'

# 3 — a participant is confirmed at the counter: register their entry
curl -s -X POST "$BASE/events/mt-zon-selatan-3-2r-q1/entries" -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"entry_token":"K7Q2M9XA","partner_reference":"cmw8r1x0a000301l4f9b2c7de"}'
# → { "entry_id": "ent_9f3b2c1d", "status": "ready", ... }

# 4 — the slip was lost: replace the token
curl -s -X PUT "$BASE/events/mt-zon-selatan-3-2r-q1/entries/ent_9f3b2c1d/token" -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"entry_token":"P4T8W2NC"}'

# 5 — read results for MT's entries
curl -s -X POST "$BASE/events/mt-zon-selatan-3-2r-q1/results:query" -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"entry_ids":["ent_9f3b2c1d"]}'

# 6 — the competition ends
curl -s -X PATCH "$BASE/events/mt-zon-selatan-3-2r-q1" -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"status":"closed"}'
```
