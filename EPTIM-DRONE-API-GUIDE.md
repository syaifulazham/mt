# EPTIM Drone API Guide

Third-party REST API for managing users, sectors, authentication, and retrieving results for drone competition events.

---

## Base URL

```
https://htttbsoeihchbeyrqdfp.supabase.co/functions/v1/eptim-api
```

## Authentication

All requests require an API key passed via the `X-API-Key` header.

```
X-API-Key: eptdk_your_api_key_here
```

API keys are scoped to a specific event. The event is automatically determined from the key - you do not need to pass an event ID.

### Obtaining an API Key

API keys are generated by organizers in the event dashboard under **API Keys > New Key**. The full key is shown once at creation time and cannot be retrieved later.

## Endpoints

### 1. Create User

Creates a new user account on the platform.

```
POST /users
```

**Request Body:**

```json
{
  "email": "pilot@school.edu",
  "password": "securePassword123",
  "full_name": "Ahmad Razif"
}
```

Or using a custom user ID instead of email:

```json
{
  "userid": "STU-2026-001",
  "password": "securePassword123",
  "full_name": "Ahmad Razif"
}
```

When using `userid`, the system generates a synthetic email: `{userid}@api.eptim.ai`

**Response (201):**

```json
{
  "id": "uuid-of-new-user",
  "email": "pilot@school.edu",
  "full_name": "Ahmad Razif",
  "userid": null
}
```

**Errors:**
- `409` - User already exists with this email/userid

---

### 2. Create Sector

Creates a new sector within the event. Sectors group users (e.g., by school, region, division).

```
POST /sectors
```

**Request Body:**

```json
{
  "sector_name": "SMK Taman Melawati",
  "region": "Selangor",
  "custom_id": "SMK-TM-2026",
  "other_details": {
    "district": "Gombak",
    "category": "Senior"
  }
}
```

| Field | Required | Description |
|-------|----------|-------------|
| `sector_name` | Yes | Display name of the sector |
| `region` | No | Region or state |
| `custom_id` | No | Your own identifier (must be unique within the event) |
| `other_details` | No | JSON object with arbitrary metadata |

**Response (201):**

```json
{
  "id": "uuid-of-sector",
  "sector_name": "SMK Taman Melawati",
  "region": "Selangor",
  "custom_id": "SMK-TM-2026",
  "other_details": { "district": "Gombak", "category": "Senior" },
  "created_at": "2026-06-18T10:00:00.000Z"
}
```

**Errors:**
- `409` - Sector with this `custom_id` already exists in the event

---

### 3. Assign User to Sector

Assigns a previously created user to a sector.

```
POST /sectors/{custom_id}/members
```

**Request Body (by user_id):**

```json
{
  "user_id": "uuid-of-user"
}
```

**Request Body (by email):**

```json
{
  "email": "pilot@school.edu"
}
```

**Request Body (by userid):**

```json
{
  "userid": "STU-2026-001"
}
```

**Response (201):**

```json
{
  "sector_id": "uuid-of-sector",
  "user_id": "uuid-of-user",
  "custom_id": "SMK-TM-2026",
  "assigned_at": "2026-06-18T10:05:00.000Z"
}
```

**Errors:**
- `404` - Sector or user not found
- `409` - User already assigned to this sector

---

### 4. Remote Login (Token)

Authenticates a user and returns a session token. The user must be assigned to a sector within the event.

```
POST /auth/token
```

**Request Body:**

```json
{
  "email": "pilot@school.edu",
  "password": "securePassword123"
}
```

Or with userid:

```json
{
  "userid": "STU-2026-001",
  "password": "securePassword123"
}
```

**Response (200):**

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "refresh_token": "abc123...",
  "expires_at": 1718712000,
  "user": {
    "id": "uuid-of-user",
    "email": "pilot@school.edu",
    "full_name": "Ahmad Razif"
  }
}
```

**Errors:**
- `401` - Invalid credentials
- `403` - User is not assigned to any sector in this event

**Usage:** The returned `access_token` can be used as a Bearer token with the standard Supabase client to access the drone simulator directly.

### 5. List Users by Sector

Returns all users assigned to a sector.

```
GET /sectors/{custom_id}/users
```

**Response (200):**

```json
{
  "sector_custom_id": "SMK-TM-2026",
  "sector_name": "SMK Taman Melawati",
  "users": [
    {
      "id": "uuid-1",
      "email": "pilot@school.edu",
      "full_name": "Ahmad Razif",
      "pilot_handle": "razif_ace",
      "assigned_at": "2026-06-18T10:05:00.000Z"
    }
  ]
}
```

---

### 6. List Challenges

Returns all challenges for the event.

```
GET /challenges
```

**Query Parameters:**

| Parameter | Description |
|-----------|-------------|
| `status` | Filter by status: `draft`, `published`, or `archived` |

**Response (200):**

```json
{
  "event_id": "uuid-of-event",
  "challenges": [
    {
      "id": "uuid-1",
      "name": "Level 1 - Basic Flight",
      "description": "Navigate through 3 checkpoints",
      "challenge_mode": "automation",
      "status": "published",
      "order_index": 0,
      "created_at": "2026-06-01T00:00:00.000Z"
    }
  ]
}
```

---

### 7. Get Challenge Results (Leaderboard)

Returns ranked results (best score per user) for a specific challenge. Sorted by score descending.

```
GET /challenges/{challenge_id}/results
```

**Query Parameters:**

| Parameter | Description |
|-----------|-------------|
| `limit` | Max results to return (default 500, max 1000) |
| `offset` | Skip this many results for pagination (default 0) |

**Response (200):**

```json
{
  "challenge_id": "uuid-challenge-1",
  "challenge_name": "Level 1 - Basic Flight",
  "challenge_mode": "automation",
  "total": 42,
  "limit": 500,
  "offset": 0,
  "results": [
    {
      "user_id": "uuid-1",
      "full_name": "Ahmad Razif",
      "email": "pilot@school.edu",
      "pilot_handle": "razif_ace",
      "sector_custom_id": "SMK-TM-2026",
      "sector_name": "SMK Taman Melawati",
      "best_score": 95,
      "max_score": 100,
      "elapsed_seconds": 38.2,
      "completed_at": "2026-06-18T14:30:00.000Z"
    }
  ]
}
```

**Errors:**
- `404` - Challenge not found in this event

---

### 8. Get All Event Results

```
GET /results
```

**Query Parameters:**

| `limit` | Max results to return (default 500, max 1000) |
| `offset` | Skip this many results for pagination (default 0) |

**Response (200):**

```json
{
  "event_id": "uuid-of-event",
  "total": 120,
  "limit": 500,
  "offset": 0,
  "results": [
    {
      "user_id": "uuid-1",

      "pilot_handle": "razif_ace",

      "max_score": 100,
      "elapsed_seconds": 38.2,
```

### 10. Check Sector Availability

Check if a sector `custom_id` is available (not already used) within the event.

```
GET /sectors/check/{custom_id}
```

**Response (200):**

```json
{
  "custom_id": "SMK-TM-2026",
  "available": true
}
```

Returns `"available": false` if a sector with that `custom_id` already exists in the event.

---

### 11. Check User ID Availability

Check if a `userid` is available (not already registered).

```
GET /users/check/{userid}
```

**Response (200):**

```json
{
  "userid": "STU-2026-001",
  "available": true
}
```

Returns `"available": false` if a user with that userid already exists.

## Error Responses

All errors follow this format:

```json
{
  "error": "Description of what went wrong"
}
```

### HTTP Status Codes

| Code | Meaning |
|------|---------|
| 200 | Success |
| 201 | Created successfully |
| 400 | Bad request (missing or invalid parameters) |
| 401 | Invalid or missing API key / Invalid credentials |
| 403 | Forbidden (user not in event sector) |
| 404 | Resource not found |
| 409 | Conflict (duplicate) |
| 500 | Internal server error |

## Example Workflow: Onboarding a School

```bash
API_KEY="eptdk_your_key_here"
BASE="https://htttbsoeihchbeyrqdfp.supabase.co/functions/v1/eptim-api"

# 1. Create the sector (school)
curl -X POST "$BASE/sectors" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "sector_name": "SMK Taman Melawati",
    "region": "Selangor",
    "custom_id": "SMK-TM-2026"
  }'

# 2. Create a student user
curl -X POST "$BASE/users" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "userid": "STU-001",
    "password": "student123",
    "full_name": "Ahmad Razif"
  }'

# 3. Assign student to the sector
curl -X POST "$BASE/sectors/SMK-TM-2026/members" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "userid": "STU-001" }'

# 4. Student logs in
curl -X POST "$BASE/auth/token" \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "userid": "STU-001",
    "password": "student123"
  }'

# 5. List challenges for students to see what's available
curl -X GET "$BASE/challenges?status=published" \
  -H "X-API-Key: $API_KEY"

# 6. Check results for a specific challenge (leaderboard)
curl -X GET "$BASE/challenges/CHALLENGE_UUID/results" \
  -H "X-API-Key: $API_KEY"

# 7. Check all event results
curl -X GET "$BASE/results" \
  -H "X-API-Key: $API_KEY"

# 8. Check results for a specific sector
curl -X GET "$BASE/sectors/SMK-TM-2026/results" \
  -H "X-API-Key: $API_KEY"
```

## Security Best Practices

1. **HTTPS Only** - All requests must use HTTPS (enforced by Supabase).
2. **Key Storage** - Store API keys in environment variables or secrets managers. Never commit them to source control.
3. **Key Rotation** - If a key is compromised, revoke it immediately from the event dashboard and create a new one.
4. **Minimal Scope** - Each API key is scoped to a single event. Create separate keys for separate integrations.
5. **Monitor Usage** - Check the "Last Used" timestamp in the dashboard to detect unauthorized access.

---

## Rate Limits

The API follows Supabase Edge Function limits:
- Requests are subject to the project's configured rate limits
- For bulk operations, add reasonable delays between requests (100-200ms)
- If you need to create many users/sectors at once, batch them with pauses between batches

---

## Notes

- The `custom_id` field on sectors is your integration key. Use a stable identifier from your system (school code, organization ID, etc.) so you can reference sectors without storing UUIDs.
- Users created via `userid` get a synthetic email. They can log in using either their userid or the full synthetic email.
- The `access_token` from `/auth/token` is a standard Supabase JWT that can be used with the Supabase client SDK for real-time features.
